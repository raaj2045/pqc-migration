## Methodology

* Validator-set size **N = 4** (smoke); validators run in 4 docker containers, each capped at `cpus=1.00, mem=1.5GiB`.
* **Validator consensus key stays ed25519** in both arms (forced by the cosmos-latest fork — see `project_cosmos_mldsa_consensus_gap.md` memory). The scheme axis varies the **user-account tx-signing algorithm** only.
* Genesis funds 8 secp256k1 senders (account_numbers 0..7) and 8 mldsa44 senders (account_numbers 8..15). Validator delegators stay secp256k1 (account_numbers 16..19).
* Pre-signed pool: 25 000 transactions per sender per arm (200 000 txs / arm). Generated by `tools/presigner sign` before the smoke runs (~7 s for secp, ~16 s for mldsa). Pool layout: JSONL of `{sender_idx, sequence, tx_b64}`.
* Loadgen replays the pool round-robin across senders at the target rate via Tendermint JSON-RPC `/broadcast_tx_sync`. A background sampler polls `/block?height=` every 500 ms and records the wall-clock observation time per block; commit time = observation time. (We avoid `block.header.time` because it is the median of the previous round's vote timestamps and runs 2–5 s in the past.)
* Pool exhaustion is a hard error (none occurred — 2999 / 25000 per sender consumed).

## Spec deviations and rationale

* **gas_limit = 250 000 per tx** (spec said 100 000). Forced by mldsa's measured `gas_used = 194 725` (vs ~50 000 for secp). 100 000 is physically impossible for mldsa in this fork: verification + bytes-read alone exceed it. 250 000 leaves ~28 % headroom for both arms; same value for both keeps the comparison fair.
* **block.max_gas = 100 000 000** (matches spec). With gas_limit=250 000 this admits 400 txs/block in theory; observed 264–270 txs/block at peak (≈67M gas/block, 67 % of cap). At 5 s block intervals this gives ~54 tx/s sustained — enough headroom for rate=50 smoke and rate=100 sweep, but tight for rate=200/500 (full sweep may need block.max_gas raised; report after first sweep run).
* **commit_timeout = 5 s** (matches spec).
* **fee = 0** (spec implicit). Required setting `minimum-gas-prices = "0stake"` in `app.toml`; with the default `0.000006stake` every tx was rejected as "insufficient fees". Zero fee makes per-tx cost a function of signature cost only — exactly what the experiment is measuring.
