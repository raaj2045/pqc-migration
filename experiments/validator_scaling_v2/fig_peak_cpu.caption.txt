Fig. 12: Peak validator container CPU usage during a run, as a function of submitted load for secp256k1 versus ML-DSA-44, three subplots one per validator-set size N in {4, 7, 16}, with a light gray reference line at the 90-percent host-saturation threshold.
Single 300-second run per (N, target rate, scheme) cell on AMD Ryzen 5 7600X under Go 1.23.5, four to sixteen Cosmos SDK validators in Docker containers each capped at one CPU; CPU is sampled by docker stats every five seconds and the peak across all validators is taken.
At low submitted rates ML-DSA-44 runs roughly 1.7 times hotter than secp256k1 (for example 55 percent versus 32 percent at N=7 rate=50); at saturating rates the relationship can invert because the secp256k1 loadgen finishes its broadcast burst earlier and so concentrates CPU work into a smaller wall-clock window.
