Fig. 9: Achieved committed throughput as a function of submitted load for secp256k1 versus ML-DSA-44, three subplots one per validator-set size N in {4, 7, 16}, with a horizontal dotted line marking each scheme's saturation throughput in its own color.
Single 300-second run per (N, target rate, scheme) cell on AMD Ryzen 5 7600X under Go 1.23.5, four to sixteen Cosmos SDK validators in Docker containers each capped at one CPU; pre-signed transactions are replayed via Tendermint /broadcast_tx_sync.
Saturation throughput falls from 67 to 50 transactions per second for secp256k1 as N grows from 4 to 16, and from 50 to 43 for ML-DSA-44; the throughput gap between schemes narrows from 25% at N=4 to 14% at N=16 because both schemes are increasingly bottlenecked by consensus rather than by signature verification.
